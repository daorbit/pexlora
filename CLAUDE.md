# Pexlora

Free image utilities in one Next.js app: remove AI metadata, convert formats, inspect image tags. Every tool works on the landing page without an account; signing in only raises the daily limit (10 → 100 files).

## Commands

- `npm run dev` — dev server on http://localhost:5778
- `npm run build` — production build
- `npm run lint` — ESLint
- `npx tsc --noEmit` — type-check

## Stack

- Next.js 16 App Router, React 19, TypeScript, Tailwind CSS 4
- Backend is Next.js itself: route handlers in `src/app/api`, server actions in `src/actions`
- MongoDB Atlas via Mongoose (users, daily usage)
- sharp (encode/convert) + exifr (read EXIF/XMP/IPTC/GPS)
- Auth: email + password (bcryptjs) or Google OAuth (code flow + PKCE, ID token verified with jose against Google's JWKS, `src/lib/auth/google.ts`, routes `/api/auth/google` and `/api/auth/google/callback`). Both end in the same JWT session cookie. A Google sign-in with an existing email links `googleId` to that user; Google-only users have no `passwordHash`.
- Mail: nodemailer over Gmail SMTP (Google App Password), sent from noreplydaorbit@gmail.com (dedicated sender; ~500 emails/day cap is accepted for now, move to a daorbit.in domain sender when volume grows)
- Icons: lucide-react only. Never type arrow or symbol characters (→ ← › ↵ etc.) in UI text; use the Lucide icon (`ArrowRight`, `ArrowLeft`, …)
- Deployed on Vercel (`vercel.json`, region `bom1`)

## Coding rules

- No comments in CSS files, and no unnecessary comments in code.
- No inline styles. Use Tailwind classes and the tokens in `src/app/globals.css`. (HTML email templates are the only exception.)
- Split code into components, hooks, utils and services; never put a whole feature in one file.
- Reuse before writing: check `components/ui`, `hooks`, `lib/utils` and `config` first. Extract anything repeated.
- Server-only modules start with `import "server-only"`.
- Copy and limits come from `config/` and `content/`, never hard-coded in components.

## Auth pages

- One centred 380px column on the page colour, same in light and dark, under a bar with the logo and a "Back to tools" link (visual base: variant E in https://claude.ai/artifact/GE3Gx37qemXvkkMiyUgBYW). The two-step email-first flow was replaced (Nov 2026) because new users landed on Sign In and only found "Create account" after typing their email. `/signin` and `/signup` both render `AuthPanel` (only the starting mode differs): heading per mode, `SignupProof` in sign-up mode, Google (`SocialAuth`, `variant="secondary"`) + "or", then one `AuthForm` with email + password (sign in, plus "Forgot password?") or name + email + password (sign up), using the `signIn` / `signUp` actions, then `AuthModeSwitch` ("New here? Create an account" / "Have an account? Sign in", a text link, never a segmented switch or tabs; it swaps the URL with `history.replaceState`, keeping `?next=`). The typed email carries over when switching (`defaultValues` + `onValueChange`). Never look up whether an email exists to pick the mode: that would reveal registered emails. Text links are foreground with a lime underline. `AuthCard` (heading via `AuthHeading`, `AuthLegalNote` with an optional free-plan line) is reused by the password and verify pages.
- Password reset: `/forgot-password` → `requestPasswordReset` (always the same answer, so it never reveals whether an email exists; skips Google-only users; 60 s resend cooldown) stores a sha256 of a random token in `PasswordReset` (TTL index, 60 min) and emails `/reset-password?token=…` (`resetPasswordEmail` template). `resetPassword` consumes the token once, sets the new hash, signs the user in and redirects to the dashboard. On phones there is no card and the form sits at the bottom of the screen. Copy lives in `content/auth.ts`.

## Security

- Rate limits: `hitRateLimit(scope, id)` (`services/rate-limit.service.ts`, Mongo fixed windows, TTL collection, fails open). Scopes and numbers in `config/security.ts`. Server actions use `actionRateLimit()`; API routes get a per-minute burst limit inside `consumeQuota` and `assertApiRateLimit()` for routes without quota. Client identity = salted SHA-256 of the IP (`lib/security/client.ts`), never the raw IP.
- Sign-up is email-verified: `signUp` stores a `PendingSignup` (bcrypt hash + HMAC of a 6-digit code, 10 min, 5 attempts, 5 sends, 60 s cooldown) and a signed `pexlora_signup` cookie, then `/verify-email` creates the user. If the email already has an account, the owner gets an "account exists" email instead, so the response never reveals which emails are registered. Google sign-in skips the code (Google verifies email).
- Sign-in always runs bcrypt (`verifyPasswordSafely`) and returns one generic error. Sessions carry `sessionVersion`; changing or resetting a password bumps it (other devices are signed out) and sends a "password changed" email. A stale or deleted-user cookie goes through `/api/auth/session-expired`, which clears it (avoids a proxy redirect loop).
- Roles change only through `actions/admin.ts` (super admin re-checked server side); no user-facing action accepts `role`, `limits` or `sessionVersion`.

## Image pipeline

- Remove Metadata and Metadata Viewer process JPG/PNG/WebP (`raster` engine) and HEIC (`heif` engine) in the browser through `lib/files/processors` (`raster.ts`, `heif.ts`); files never leave the device. They share the stripper/injector code with the server and the exifr parsing in `lib/metadata/exif-report.ts`. Rotated photos keep a minimal EXIF with only Orientation (`lib/image/orientation.ts`), which `leftoverTagCount` ignores.
- HEIC is `serverReadable: false` (sharp's prebuilt build can't decode it): only tools with `localCapable: true` in `toolBehaviors` accept it; `formatsOfKinds`/`acceptAttribute`/`getFileError` take a `localCapable` flag. HEIC cleaning zero-fills the Exif/XMP items found through `iinf`/`iloc` and renames their item type (`lib/files/containers/heif.ts`); rotation lives in `irot`/`imir` and survives.
- Compress and Resize run in the browser for JPG/PNG/WebP/HEIC (`localCapable: true`): `processInBrowser` (`lib/files/raster/browser-raster.ts`) decodes on the main thread (`decodeImage`, EXIF rotation, HEIC), checks `BROWSER_MAX_PIXELS`, and posts the `ImageBitmap` to `raster.worker.ts` (OffscreenCanvas + step-down scaling in `surface.ts`; encoders in `encoders.ts`: mozjpeg via `@jsquash/jpeg`, libwebp via `@jsquash/webp`, palette PNG via `upng-js`, lossless PNG via `convertToBlob`; all dynamically imported). HEIC comes out as JPG. Compress-to-target uses the shared `searchTarget` (`lib/image/target-search.ts`), which the server's `compressToTarget` also uses. If the browser can't (no Worker/OffscreenCanvas, too many pixels) and the file is ≤ `SERVER_IMAGE_SIZE_MB`, `services/local-tools.ts` falls back to the API; server results carry `uploaded: true` so the "Processed on your device" chip stays honest. Size limits: `FILE_SIZE_LIMITS_MB.image` (10 MB, Pro 20 MB) for in-browser images, `SERVER_IMAGE_SIZE_MB` (4 MB) for anything posted to the API.
- AVIF/TIFF/GIF cleaning and every other image tool post to `/api/images/*`; the client validates type/size first (`lib/image/validate.ts`).
- `inspect` returns an `ImageReport` (groups: C2PA, PNG text, XMP, IPTC, GPS, EXIF, ICC; AI entries flagged).
- `clean` cuts metadata segments out of JPEG/PNG/WebP bytes (`lib/image/strip`, lossless, keeps ICC) and re-inspects the output to report leftover tags. Server-side, only rotated images (EXIF orientation > 1) and other formats re-encode.
- `edit-metadata` strips losslessly, then splices in EXIF/XMP taken from a 1x1 carrier image (`lib/image/inject`, `metadataCarrier`).
- Encoder speed presets in `lib/image/encode.ts`: `fast` (clean/edit fallback), `balanced` (convert, resize), `smallest` (compress). Don't bring back mozjpeg at q100, WebP effort 6 or AVIF effort 4: they're many times slower for little or no size gain.
- Routes run the quota check in parallel with the work (`withFileQuota` / `withAiQuota`); paid AI model calls wait for the quota. The client queue runs `PARALLEL_FILE_JOBS` files at once.
- `convert` takes `format` (jpeg/png/webp/avif) and `quality`.
- sharp reports AVIF as `heif`; `toOutputFormat` maps it back.
- Quota: `consumeImageQuota` counts per user or per hashed IP per UTC day in Mongo. If Mongo is unreachable it fails open.

All environment variables live in `.env.local` (the only local env file, gitignored; production values are set on Vercel): `MONGODB_URI`, `MONGODB_DB_NAME` (default `pexlora`), `SESSION_SECRET`, `APP_URL`, `SMTP_HOST/PORT/SECURE/USER/PASS/FROM`. Never commit `.env.local`.

## Gotchas

- Every CSS grid needs a base column count (`grid grid-cols-1 … lg:grid-cols-[…]`), never only breakpoint columns. A grid with no base columns gets one `auto` track sized to its widest unwrapped content (`truncate` text, `whitespace-nowrap`), so on phones the page becomes ~1000px wide and the browser zooms everything out. This broke the dashboard on mobile.

- `<html>` must keep `data-scroll-behavior="smooth"`: `globals.css` sets `scroll-behavior: smooth`, and since Next 16 the router only disables it during navigation when that attribute is present. Without it, route changes smooth-scroll and stop part-way instead of jumping to the top. The dashboard sheet scrolls itself, so `ShellScrollArea` resets it on every pathname change.

- Vercel caps request and response bodies at 4.5 MB, so anything posted to `/api/images/*` is limited to `SERVER_IMAGE_SIZE_MB` = 4 (`config/limits.ts`). Bigger files need browser processing (see Image pipeline), not a higher number.
- Atlas must allow Vercel's IPs (Network Access).
- We remove metadata only. Never claim to remove pixel watermarks (SynthID) or beat AI detectors.
